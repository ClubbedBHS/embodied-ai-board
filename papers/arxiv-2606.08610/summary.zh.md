# HARBOR：面向智能体机器人强化学习的 Harness 框架

> HARBOR 以标准化命令、工件、可执行门和经验库组织多个智能体，自动完成机器人 RL 的环境配置、奖励设计、训练调参与真实部署准备。

## 研究问题

机器人 RL 的主要成本往往不在算法本身，而在依赖安装、任务实现、奖励塑形、训练诊断、超参数搜索和渲染验证。把这些工作交给一个长上下文智能体容易产生隐蔽错误，也无法稳定复用经验。论文把自动化问题重新定义为 harness engineering：为智能体建立有边界、可验证的操作环境。

## 核心方法

HARBOR 将工作流分成环境搭建、任务生成、奖励构造、域随机化和训练调优等阶段，每阶段由专门智能体通过受控命令修改代码并产出持久工件。可执行 gate 检查奖励分解、环境步进、指标、渲染和训练阈值，避免仅凭日志文本判断成功。

系统并行运行多个试验，把成功配置、模拟器约定和失败修复写入经验库，后续任务可检索复用。人类可以提供启发式知识，但最终结果必须通过训练与渲染门验证。

## 主要贡献

1. 将机器人 RL 自动化系统化为命令—工件—门—知识的 harness。
2. 以有界阶段和专用智能体替代单一无约束长流程。
3. 在六个模拟器、16 个任务和真实机器人部署中验证端到端工作流。

## 数据与训练

评测覆盖 IsaacLab、Bi-DexHands、ManiSkill、Genesis、MJLab 和 Loco-Mujoco，共 16 个任务，并使用多个 RL 算法。真实部署涉及双 Franka 等平台。框架运行需要 LLM 调用和大量训练计算；论文没有确认公开代码或完整运行轨迹。

## 实验与结果

HARBOR 在 Insert-Drawer、Stack-Cube 等长时任务上成功，而 Eureka/REvolve 基线出现零成功或部分失败（Sec. 4，Table 2）。相对默认配置，IsaacLab 的训练曲线 AUC 提高约 1,300%，可比任务达到阈值快 18.6%；Loco-Mujoco AUC 提高 238%、阈值时间降低 60.4%；Bi-DexHands AUC 提高 12.3%（Appendix D.4，Table 4）。完整流程报告约 71 美元智能体成本，消融版本更高。

## 局限性

结果依赖当前 LLM 能力、提示与 API，成本统计会快速变化。自动生成奖励仍可能优化错误目标，gate 只能覆盖预先定义的错误类型。六个框架虽广，但任务数量仍有限；开源状态不明确。

## 为什么值得关注

机器人 RL 规模化需要的不只是新算法，也需要让工程流程可审计。HARBOR 对命令权限、产物和验证门的强调尤其值得关注，因为它把“智能体写代码”转换为可重复的实验系统。
